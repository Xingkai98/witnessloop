# Design: archive-arrival-d-side

> 状态：草稿（grill 已完成 → 见 `reviews/grill-design.md`；对抗轮进行中）。
> **停轮门**：本文件 §6 逐条列出「为什么没有需要用户拍板的问题」，**其中 Q1 是 grill 提出、由本次改判据
> 自行裁定的**（另一条路也如实写下，供用户复核）。

## 0. 一句话

`git` 配不上 rename 时会留下**一条 `D`（旧 active 路径）+ 一条 `A`（archive 路径）**；
把那条**配得上对**的 `D` 认成「那次搬移的另一半」，使它**免解释事件**、并把它的源 id 从 active id 里排除。

## 1. 现状（逐行实测）

- **`D` 记录的字段落位**：`gitutil._parse_name_status`（`src/witnessloop/gitutil.py:210-225`）对非 `R`/`C` 记录
  走 `Change(raw, fields[i + 1])`（`:224`）——即被删路径进 **`path`**、**`old_path` 留 `None`**（`gitutil.py:16-22` 的 `Change`）。
- **受保护写入的豁免**：`checkcmd._protected_writes`（`src/witnessloop/checkcmd.py:346`）逐条记录判
  `_archive_move_exempt(change, pol, arrivals)`（`:373`）；而后者（`:324-343`）**第一句**就是
  `if not change.old_path: return False`（`:335`）
  ⇒ **`D` 记录永远拿不到豁免**——这正是 issue #31 那条红的来源。
  （`:339` 再要求 `old_path` 落在 `<changes_root>/<active-id>/` 下、`:342-343` 要求 `new_path` 落在某个到达目录下。）
- **到达组带 source_ids**：`contract.archive_arrivals`（`contract.py:253-324`）里 `group` 是
  `under_path(change.path, directory)` 的记录集合（`:300-302`），`sources`（`:314-320`）从 `group` 里
  **`old_path` 落在 `<changes_root>/<active-id>/` 下**的记录取——即 **git 自己配对出来的**那些源 id。
  那些 `old_path` 就是「这条到达目录是从哪个 change 搬来的」的**机器证据**。
- **幽灵 id 的既有处理**：`contract.changed_change_ids`（`contract.py:355-417`）用 `moved_sources`（`:378-392`）
  把源 id 从 active id 里排除。它只扫 `arrival.records`（= 新路径落在到达目录下的记录）⇒
  **纯 `D`+`A` 形态下 `moved_sources` 是空的**（没有 `R` 把源 id 带进来）。
  ⚠️ 混合形态（同一次 move 里既有配上的 `R`、也有配不上的 `D`）**今天已经没有幽灵 id**：
  配上的那些 `R` 已经把源 id 放进 `moved_sources`，而 `excluded`（`:393-402`）按 **id** 排除、同时看
  `(old_path, path)` 两侧 ⇒ 那条 `D` 的 `path` 顺带被排除。**所以 issue #31 的实测里只有「受保护写入」那一条红。**
- **复现（issue #31 原文）**：base `8e5fc83b`、head `d94c08334` + 归档目录名重绑 manifest ⇒
  `git diff -M --name-status` 里**只有一条 `D`**（`…/guard-write-allowlist/workflow-events.jsonl`），
  `check` 报 **1 项**「受保护路径被写入，但没有结构化解释事件」。本 change 在自己的测试里复刻了这个形态。

## 2. 决策

### D1 判据：**覆盖**——归档目录必须装下源 change 的**全部**文件

一条 `D` 记录（`status[:1] == "D"`，被删路径在 `change.path`、`old_path` 为空）SHALL 被认成
**某次到达搬移的另一半**，当且仅当**存在一个到达目录 `A`**（`archive_arrivals(...)` 的结果，判据 1/2/3/5 一条不放松）同时满足：

1. **源侧是 active 的一个文件**：`normalize(change.path)` 形如 `<changes_root>/<id>/<sub>`，`<sub>` **非空**
   （记录不能正好是目录本身），且该路径**不在** `<changes_root>/archive/**` 下；
2. **覆盖**：`<id>` 在**基准树**（`M = merge-base(base, head)`）里的**每一个**文件
   `<changes_root>/<id>/<sub'>`，都有一条**落在 `A` 之下、相对子路径逐字相同**的记录：
   `f"{A.directory}/{<sub'>}"` —— 该记录可以是
   - 一条 `R`/`C`（`old_path` = 源路径、`path` = 归档路径），**或**
   - **一条 `A`**（`path` = 归档路径）**且** 该源路径在本次 diff 里有一条 `D`。

⇒ 该 `D` 记录 SHALL 免于「受保护路径被写入，但没有结构化解释事件」（**两档**受保护路径都适用）；
其源 id SHALL 与 rename 的旧侧一样**从 active change id 里排除**。

**为什么是「覆盖」而不是「配对一条 + 几个额外条件」**（**四轮独立审阅**的实测史）：

前三版判据都是「给单条 `D` 找一条配得上的 `A`」+ 若干合取项，结果**每一版都被造出一条绕过**：

| 版本 | 判据 | 被谁破 | 怎么破的 |
|---|---|---|---|
| 甲 | 同相对子路径 的 `A` + 到达 | **grill 的 G1** | 删掉整个 active change `b`：骨架子路径与任何到达目录都重合（`proposal.md`/`design.md`/…）⇒ 凑齐 |
| 乙 | 甲 + 「源目录已离开 head」 | **A1 的 S8** | **零蓄意**：删整个 change + 别处重建 manifest ⇒ git 自己给出跨 change 的 `R055` 配对 |
| 丙 | 甲 + 「`A.source_ids == {<id>}`」 | **A2 的 P7 / A3 的 PFIVE** | 自造一个过判据的到达目录，把源的一个文件搬进去当**钥匙**（A2）；再把源的其余部分**删干净**让「源已离开」也成立（A3） |
| **丁（取）** | **覆盖**（上面第 2 条） | — | **要伪造它，就得把 `<id>` 的**每一份内容**都放进 `A`** ⇒ 那**就是**那个 change 的归档 |

**A3 给出的根因**与它为什么在这里失效：A3 指出「只要攻击者能控制整个 diff，任何**结构**证据都能被一起造出来」——
对甲/乙/丙成立，因为它们要的是**一条**配得上的记录（`≤O(1)` 个额外动作）。
**覆盖**要的是「源的**全部**文件都在 `A` 里」：伪造它的**唯一**办法就是把源的内容真搬过去，
而那时**它就是**那次搬移（`_content_provenance_ok` 也要求内容确实是本次搬来的）⇒ **判据是充分的，不只是启发式的**。✓

**为什么不再需要「源目录已离开 head」那一条**：覆盖里「源的每一个文件都有落点」+ 到达判据 5（内容来源）
已经蕴含「源的内容整体去了 `A`」；再要求目录消失是**冗余**的（A4-4：那一条的代价说明此前也写错过）。

### D1-承诺面（**本判据承诺什么、不承诺什么**）

1. **它放行 issue #31 的形态**（源侧那条掉队的 `D`）——正向用例钉住；
2. **单调性**：对**任何**输入，**本 change 判出的 findings ⊆ 改动前判出的 findings**
   ——即**不新增任何红**、也不误伤（⚠️ A4-1 订正：早先写成「豁免集 ⊆ 豁免集」是**方向写反**；
   正确的是**豁免集变大、findings 变小**）。
   **代价面**（唯一会「少豁免」的形态）：**部分搬移**（源 change 仍在，只搬走一部分文件）
   ⇒ 覆盖不成立 ⇒ 那些 `D` 仍要事件（**与改动前同结论**，见 §3 N-m）。
3. ⚠️ **蓄意伪造**：覆盖把上面那张表里的四条路**全部堵死**（它们都靠「只搬一两个文件」冒充搬移）。
   本判据**不宣称**「任何伪造都挡得住」——那是整个 capability 的既定边界
   （`docs/gate.md §7`：「默认只防漂移，不防蓄意伪造」，真锚是远端 branch protection + required check）；
   但**已实测的伪造路径一条都不剩**（四轮各造一条，这一版全挡）。

### D2 落点：一个纯函数、一处消费（判据只此一份）

新增 `contract.d_move_halves(changes, policy, arrivals, view, head_rev) -> frozenset[str]`：
（⚠️ A3-3：早先的签名漏了 `view`/`head_rev`——**第 4 条要读 head 树**
（`view.entry(head_rev, f"{root}/{id}") is None`，与 `changed_change_ids:391` 同谓词），
只有 `changes/policy/arrivals` 表达不了它。）
返回**属于搬移另一半的 `D` 记录的规范化路径**集合（D1 的判据全在这里，只此一处）。
`checkcmd._archive_move_exempt`（`:324-343`）改成：`change.old_path` 那条路照旧；
`D` 记录（`old_path` 为空）则查集合成员。

⚠️ **`changed_change_ids` 不动**（A1 的 A1-2 订正）：早先写过「把 `D` 侧的源 id 并进 `moved_sources`」——
**那半已删除**，两个理由：
① 在「恰为一个源」的锚下，**纯 `D`+`A` 形态恒不成立**（`source_ids` 为空 ⇒ `d_move_halves` 恒空）
   ⇒ 那半在最好的情况下是 no-op；
② 在最坏的情况下它是**第二个洞**：把源 id 无条件并进 `moved_sources` 会让一个**还活着**的 change
   从 active id 里消失、逃掉契约校验（A1 的 S2 实测：`2 个 change 目录 → 1 个`）。
既不必要又危险 ⇒ **不碰**。（`:381-383` 那个死分支也**不**顺手动：它是独立于本 change 的既有代码，
动它要改既有钉子测试，超出本 issue 的面——已登记在 §4 R5。）

### D3 只认 `A`，不认别的

配对的另一半 SHALL 是**一条 `A` 记录**（`status[:1] == "A"`）。
`R`/`C` 记录天然带 `old_path`，走既有那条路；`M`/`T` 更不认（它们不表示「搬进来」）。

### D4 不改到达判据

`archive_arrivals` 的判据 1/2/3/5（`contract.py:290-313`）**一条不动**。
本 change 只在「到达组**之后**的消费面」上加一条：`D` 记录的对侧。

### D5 事件类型与 id 语义照旧

豁免的语义是「这条记录**不是**删除、是搬家的旧侧」⇒ 它本来就不该要事件。
**不**新增事件类型、**不**改 `_protected_writes` 对 `policy.protected_paths` 与不变集的两档规则。

## 3. 否定面（SHALL NOT 被本 change 放开；逐条有测试）

> ⚠️ **覆盖判据之后，本表每一条都由「覆盖不成立」或「不是到达」统一挡住**（不再有「登记为非目标」的类别）——
> 四轮独立审阅各造出的绕过（G1 / S2 / S8 / P7 / PFIVE）**全部**是「只搬了一两个文件」，
> 而覆盖要求「源的**每一个**文件都在 `A` 里」⇒ 全部不成立。

| # | 形态 | 为什么不被豁免 |
|---|---|---|
| N-a | 往**已存在**的归档目录里搬东西（`archive/<name>/` 在基准树里有 entry） | 它不是**到达** ⇒ 不在 `arrivals` 里（第 3 条的前提就不成立） |
| N-b | **单独**删一个 active change 的文件（diff 里没有配得上的 `A`） | 第 2 条不满足 |
| N-c | 删掉**整个** active change 目录（同一次 diff 里**没有**任何到达目录） | 第 3 条不满足（没有 `A`，也没有 source_ids） |
| N-d | 删掉整个 active change `b` **且**别处恰有一次正当搬移的到达目录 `A`（子路径重合） | **覆盖不成立**（`b` 的文件在 `A` 里没有落点）——**grill 的 G1，实测那一版会漏** |
| N-j | 在**仍然活着**的 change `b` 里 `git mv` 一个小文件进到达目录 `A`，再删 `b` 的受保护文件 | **覆盖不成立**（`b` 的其余文件没有落点）——**A1 的 S2**（甲 那版会 `rc=0 全绿`） |
| N-k | **零蓄意**：删掉整个 change 目录 + 在别处重建 manifest ⇒ git 自己给出**跨 change 的 `R055`** 配对 | **覆盖不成立**（被删 change 的文件没有落点）⇒ 那些 `D` 保持要事件（保守）——**A1 的 S8** |
| N-l | **自造**一个到达目录，只把仍活着的 `<id>` 的**一个**文件搬进去当钥匙，再删 `<id>` 的受保护文件 | **覆盖不成立**（`<id>` 的其余文件在 `A` 里没有落点）——**A2 的 P7**（丙 那版会 `rc=0 通过 ✓`，覆盖挡得住；A4 已复核） |
| N-m | **部分**搬移（源 change 仍在 head，只搬走一部分文件） | **覆盖不成立**（源里有文件没有落点）⇒ 那些 `D` 仍要事件（**与改动前同结论**，本 change 只减少红、不新增） |
| N-n | **蓄意 PFIVE**（A3）：自造到达目录 + 只搬源 `b` 的一个文件当钥匙 + **把 `b` 的其余部分全删** | **覆盖不成立**（`b` 的其余文件在 `A` 里没有落点）⇒ 仍要事件——**A3 造的那条在覆盖下被挡住** |
| N-o | **蓄意**：把源 `b` 的**全部**内容都放进 `A`（含它那些受保护文件），再删掉 `b` | **覆盖成立 ⇒ 豁免（这是对的）**：那时 `A` **就是** `b` 的归档（`A` 会按归档 change 走同一套契约与证据门禁）。**这不是缺口，是判据的充分性** |
| N-e | 把**受保护文件从 active change 外**搬进到达目录（如 `openspec/specs/x.md`） | 第 1 条不满足（源不在 `<changes_root>/<id>/` 下） |
| N-f | `D` 的路径正好是 `<changes_root>/<id>` 本身（`<sub>` 为空） | 第 1 条要求 `<sub>` 非空 |
| N-g | 重建已存在的 `reviews/*.manifest.json`（`M`） | 与 `D` 无关；既有 1 格红的回归照旧 |
| N-h | `archive/<name>/` 缺必需件 / 内容来源存疑 / 是符号链接 | 不在到达组里 ⇒ 第 3 条不成立 |
| N-i | **纯 `D`+`A` 搬移**（一个 `R` 都没有，但**覆盖成立**：源的每个文件都有对应的 `A`） | **覆盖成立 ⇒ 豁免 ✓**（⚠️ A1/A2 的早先版本要求 `source_ids` 非空，反而把这一形态误判成要事件；覆盖把这条**修正**成放行） |

## 4. 风险

| # | 风险 | 处置 |
|---|---|---|
| R1 | **纯 `D`+`A` 搬移不被豁免**（N-i）⇒ 那种形态下源侧受保护文件仍要事件 | 如实写进 `specs/` 的 Scenario（**与改动前同结论**：本 change 只**减少**红、不新增） |
| R2 | **部分搬移**（N-m）下那些 `D` 仍要事件 | **与改动前同结论**（改动前 `D` 一律要事件）⇒ 本 change 只减少红；覆盖要求「源整体搬走」，那正是「归档」的定义 |
| R3 | 伪造空间 | **覆盖是充分的**（装下源的全部内容 ⇒ 那就是归档）；**四轮独立审阅各造的一条绕过全部被它挡住**（见 §2 D1 的表）。门禁的既定边界（`docs/gate.md §7`：防漂移不防伪造）仍然成立，但本判据**不再给伪造留已实测的口子** |
| R4 | 到达判定用的树读不出来 | 既有路径已经 fail-closed（`checkcmd` 在到达判定前就 `GitError` ⇒ 报 finding 退 1）；本函数不需要额外读树 |
| R5 | `changed_change_ids:381-383` 是**死代码**、而既有钉子测试对它是**空的**（grill 的 G4 + A1 复核） | **本 change 不动它**（超出本 issue 的面，动它要改既有测试）；如实登记，留给专门的小清理 |
| R6 | 覆盖要求「源整体搬走」⇒ 部分搬移的未配对文件仍要事件 | **与改动前同结论**（不新增红）。A2/A3 实测：正当的**完整**归档（含 issue 的形态）里覆盖恒成立；A4 的 19 探针里**没有一次** findings 变多 |

## 5. 测试策略（TDD，先红后绿）

1. **正向**：复刻 issue #31 的形态（active change 在 base、head 里整体进 archive，其中一个受保护文件是 `D`+`A` 而非 rename，
   **其余文件有配上的 `R`**）⇒ `check` **通过 ✓**（改前红 1 项）。
2. **否定面**：§3 的 N-a…N-m 逐条一条测试（能端到端就端到端；`<sub>` 为空这类只能**纯函数级**测）。
   **三个杀手用例**（分别来自三轮审阅，改前各自会漏）：**N-d**（grill 的 G1）、**N-j**（A1 的 S2）、
   **N-l**（A2 的 P7：自造到达目录当钥匙 ⇒ 只有「恰好一个源 ∧ 源已离开」一起才挡得住）。
3. **纯函数面**：`d_move_halves` 的**覆盖**算法（相对子路径逐字相等、前缀边界、`./` 归一化、`<sub>` 为空/尾斜杠、
   源在基准树里为空、源里有文件在 `A` 下没有落点）。
4. ⚠️ **单调性**（承诺面第 2 条）：拿既有 F/N 组用例 + 四轮审阅造的那几条形态，
   断言「本 change 的 findings ⊆ 改动前的 findings」（不新增红、不误伤）。
4. **回归**：`tests/test_archive_awareness.py`（18 条 F 组 + 6 条 N 组）与 `tests/test_archive.py` 全绿。
