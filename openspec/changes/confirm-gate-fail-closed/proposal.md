## 背景

`check` 对 grill 报告（`stage=grill` 的 manifest 绑定的那份决策记录）有**三条正文判据**
（`src/witnessloop/evidence.py`）。三条里**两条 fail-closed、一条 fail-open**：

| 小节 | 缺失 / 标题不逐字时的行为 | 实现位置 |
|---|---|---|
| `## Confirmed Decisions` | **红**（顶层 bullet 少于 3 条）✓ | `evidence.py:121-133` |
| `## User Confirmation` | **红**（`缺少 ## User Confirmation 小节`）✓ | `evidence.py:140-142` |
| **`## Open Questions`** | **静默跳过**：`sections.get(OPEN_QUESTIONS_TITLE) or ""` ⇒ 取不到就没有 `Q<n>` ⇒ 逐条确认循环**一次都不跑** ❌ | `evidence.py:144-145` |

三个标题常量是**逐字**的（`evidence.py:24-26`），而 `_sections()`（`evidence.py:52-64`）
用**标题字符串本身当字典键**。于是 `## Open Questions` 一旦被写花（加限定词、改语种、换措辞），
取到的就是 `None` → `or ""` → 空串 → **没有任何 `Q<n>`** → 循环零次迭代。

**后果**：把标题改成 `## Design-Level Open Questions（…）`，「**每个 Open Question 都必须有用户确认**」
这条规则**完全失效**。而它正是「停轮确认门」（`templates/grill.md` 硬约束 ③）的**机械保障**——
`guard` 用它拦「没拿到用户拍板就写代码」，`check` 用它拦「没有用户确认的合并」。

`design.md §1.2` 给出**同一份正文、只换标题**的对照实验：清空全部确认后，
逐字标题 ⇒ **红 3 项**；非逐字标题 ⇒ **绿 0 项**。⇒ 这条判据今天**形同虚设**：它挡住的只是
「标题恰好写对」的人。

## 目标

1. **`## Open Questions` 判据 fail-closed**：与 `## User Confirmation` 对称——**小节缺失即红**，
   而不是「取不到就当空、当空就跳过」。
2. **堵住 `design.md §1.5` 实测出的那个绕过洞**：`## Open Questions` 留着但**空着**（`（无）`）、
   真问题写进一个**近义标题**的小节 ⇒ 今天绿。**只把「缺失」判红是不够的**
   （title 在、内容空 ⇒ 仍绿），必须让「像 Open Questions 的小节」的内容也进入判据。
3. **定死歧义与优先级**：同一份报告出现**两个都像**的标题怎么办、同一个标题出现**两次**怎么办
   ——**一律取并集、不许静默丢一节**（沿用 `_sections()` 既有的 `setdefault` 合并语义，见 `design.md §1.4`）。
4. **判据仍只有一处实现**：`grill_evidence_findings` 是 `check` 与 `guard` 共用的**同一个纯函数**
   ⇒ 本 change 只改这一处，`guard` 随之同改（不新增第二个判据面）。
5. **要求小节存在 ⇒ 产出方必须产出它**：复核并（必要时）收紧 `templates/grill.md` 的产出义务
   ——否则「用了新模板生成的报告」会被新判据自造红。
6. **确认侧不得被一段「示例」关掉**（对抗轮 R2 复审挖出，**并进本 change**）：
   `_sections()` 今天**不识别代码围栏** ⇒ 报告里**引用**一段含 `## User Confirmation` + `- **Q1**: …`
   的示例，那段会被当成**真小节**、确认**被取到** ⇒ 一份**真有未确认 `Q<n>`** 的报告**变绿**
   （实测修前 **0 条**、修后 **2 条**）。它与 M4 声明的「围栏不跳」是同一件事的两面，
   而**确认侧那一面是假绿**（消不掉）⇒ **修掉**（`design.md` D9；存量代价实测 **211 份 0 影响**）。
7. **正文判据逐份生效**（第 ⑥ 项实测逼出的范围）：`evidence.py:210` 今天只校验**排序第一份**
   `stage=grill` manifest ⇒ 一份合规诱饵即可让正文判据**整段失效**
   （实测，**标题逐字的**不合格报告：诱饵不在 4 条、诱饵在场 0 条）⇒ 一并修掉
   （`design.md` D8；存量代价实测 **0**）。
   ⚠️ **覆盖范围（对抗轮 M-B 收窄）**：D8 关掉的是「**同 stage 多份、排序最前那份被校验**」
   这**一个变体**；它**关不掉**「真决策记录绑到别的 stage、`stage=grill` 绑一份合格 stub」
   ——那条是**本门禁的前提**（「`stage=grill` 那份 manifest 绑定的报告就是决策记录」），
   已写进 spec 的边界声明 11 与停轮项 Q4 的例子 2。**不**做「关掉它」的承诺。

## 非目标

- **不改** `## Confirmed Decisions` 的「≥3 条 + 每条带 `来源:`」判据与其块级口径的**定义与实现**。
  ⚠️ **收窄（对抗轮 R4）**：它的**输入面**因 **D9**（跳过代码围栏）而变——写在围栏里的 `来源:`
  或整条 bullet 不再进入该小节 ⇒ 那些输入上会**多报**（实测 0 → 1 条）。方向 fail-closed，
  已进 `design.md §8.1` 的 B7 与 spec 边界声明 14。
- **不改** `_sections()` 的 `setdefault` 合并语义（同名标题合并是**既有**行为，
  且 `## User Confirmation` 今天就依赖它——`design.md §1.4` 有实测）。
- **不引入**「Open Questions 必须非空」「每条 Open Question 必须写推荐答案 / 具体例子」这类**内容质量**判据
  ——那些是 `templates/grill.md` 的**流程规定**，机械判不了「例子好不好」（本仓一贯口径：
  机械门只保证**存在**可绑定的证据，不保证**质量**）。
- **不引入** `design_hash` 或任何「报告 ↔ design 内容」绑定。
- **不碰接入方的仓**：那 1 份存量报告的改名/补节**不由本 change 执行**（跨仓动作，见 `design.md §2.6` CQ6）。
- **不收紧** `## Confirmed Decisions` / `## User Confirmation` 的标题口径（它们今天就 fail-closed，
  没有需要修的 fail-open；把三条一起换成近义匹配只会**扩大**误伤面）。
- **不**试图机械认定「哪份文件才是真决策记录」（**D8 覆盖不到的那一类**，见目标 7 的 ⚠️）：
  三条可行路（规范文件名 / 全篇扫正文 / 机械认定）都被评估并否掉（`design.md` D8），
  该边界**声明**而不**声称**关掉。
- **不改** `_sections()` 的**签名与合并语义**（同名标题合并照旧）——
  ⚠️ 但**「跳过代码围栏」是本 change 要做的**（D9：围栏里的一段 `## User Confirmation` 示例
  会让未确认的 Q **变绿**，修前 0 条 / 修后 2 条；存量代价实测 **211 份 0 影响**）。
- **不**识别 `### `（H3）标题、**不**判定确认答复的真伪（占位判据有**长度阈值**，
  见 spec 声明 12 的三层口径）、**不**让围栏内的 `Q<n>` 进入判据（声明 13，D9 的对称代价）——
  三条只写进 spec 的边界声明（第 4 / 12 / 13 条）与停轮项 Q4。
- **不**再收窄 `_sections()` 的**标题识别面**（非 H2 / 带反引号的标题仍判红）——
  方向 fail-closed，已进 §8.1 的面清单。
- **不**改 `_confirmations` 的「同键后写覆盖」语义（Q4 第 9 类 / 声明 15）——两条改法
  （任一行为实质即算确认 / 全部行都须实质）都会开新口子或误伤「先占位、后补真答复」的**修复动作**。
- **不给 D2 的 (b) 加「否定词黑名单」**（`Non-` / `未` / `非` …）来挡 `## Non-Open Questions`
  这类**多收**：那是**枚举否定词**，永远不完整，且让规则从「一条正则」退化成「正则 + 词表」。
  ⇒ 方向是 fail-closed（多要一条确认），**接受**并写进 §8.1 的 **B8** 与声明 6（Q4 第 8 类）。

## 验收

- **症状级**（fail-open 的两面各自可判定，见 `design.md §5`）：
  - ① **标题写花**（整份报告没有逐字小节）⇒ **红**，且诊断**列出那些含 `Open Questions` 字样的标题**
    （今天绿、且无任何提示）；
  - ② **逐字小节留着但空、真问题塞近义小节** ⇒ **红**（该 Q 未经确认）（今天绿）；
  - ③ **诱饵 manifest**（排序在前、绑一份合规短报告）⇒ **真报告那几条照样逐条报出**（今天 0 条，见 ⑥；
    ⚠️ 该 fixture 的报告**标题必须逐字**——否则今天本来就少一条，会「因为错误的理由通过」）；
  - ④ **围栏里的 `## User Confirmation` 示例**（报告真有未确认 Q）⇒ **红**（今天 0 条，见目标 6）。
- **对称性**：`## Open Questions` 缺失与 `## User Confirmation` 缺失**报同一种 finding**
  （`缺少 \`## <标题>\` 小节`）——两条判据此后同形。
- **否定用例（必须照样红 / 必须红，防绕过）**——⚠️ 前缀用 **`X`**（`design.md §5.3` 的
  `X1–X16`）；`N1–N33` 是**审阅者**的非阻塞项编号（R2 的 N11 指出两套曾撞车）：
  - **X1** 标题改成**完全不含** `Open Question` 字样的花哨标题（如 `## 悬而未决的疑问`）⇒ **红**；
  - **X2** 逐字小节**空着** + 真问题写进近义小节 ⇒ **红**（不是「小节在就放行」）；
  - **X3** 逐字小节在、`## User Confirmation` 也全有 ⇒ **仍绿**（不误伤；
    本仓 `archive-awareness` 那份**两处候选标题**的报告即此形态）；
  - **X4** `## User Confirmation` 缺 ⇒ 仍红（既有判据一条不软）；
  - **X5** `## Confirmed Decisions` < 3 条 ⇒ 仍红（既有判据一条不软）；
  - **X8** **诱饵 manifest 在场 / 不在场两种造法结论一致**（都报真报告那几条）⇒ 诱饵不得改变判定；
  - **X11** **围栏里的 `## User Confirmation` 示例不得当真确认**（拿掉围栏 ⇒ 变绿，围栏是唯一差别）；
  - **X13** **围栏里的真问题不进判据**（今天 1 条 ⇒ D9 之后 0 条）——**刻意接受**（Q4 第 6 类 / 声明 13）。
  - **X16** **同一编号确认两次 ⇒ 末行赢**（占位在前 ⇒ 0 条；对调 ⇒ 1 条）——**刻意接受**（Q4 第 9 类 / 声明 15）。
- **存量影响 = 0**（提案的语义下，实测）：接入方 63 份 + 本仓 8 份 `stage=grill` 报告**全部不新红**
  （`design.md §1.6`）；D8 的逐份校验同样**新红 0**（本仓 8 个已落证据的 change 每个 stage 恰好 1 份，
  `design.md` D8 表）。
  ⚠️ **前提（必须连读）**：那 63 份报告所在的检出里 `*.manifest.json` = **0 份** ⇒ 它们**今天根本
  不被门禁评估**；「新红 0」是「**假如它们都被绑定**」的模拟（保守用法），

## 测试策略

TDD。判定面是 `evidence.grill_evidence_findings` 的**一处分支** + `stage_manifest_findings_in_change`
的**一处取法**（逐份而非 `matching[0]`）+ `_sections()` 的**一处新语义**（跳过代码围栏），
用例密集在**五件容易漏的事**上：
①「标题写花 ⇒ 必须红」而不是静默；②「小节在但内容空 + 近义小节装真问题 ⇒ 必须红」；
③「**不误伤**——两处候选标题并存时取并集且不红」；④「**诱饵 manifest 不得改变判定**」；
⑤「**围栏里的示例不得当真确认**」。
外加**语义钉子**：候选集合的边界（哪些标题算、哪些不算）要有**正反两面的显式用例**，
否则这条判据会在下一次「顺手放松一点」时静默退化。
